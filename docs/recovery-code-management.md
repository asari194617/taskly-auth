# 復旧コード再発行仕様

復旧コードの正本は認証 DB の `recovery_codes` とする。移行時は既存行と使用済み状態をそのままコピーし、旧 API と新 API が同時に消費・再発行しないことを切り替えゲートとする。

- `POST /auth/recovery/generate` は認証 UI と一致する `Origin`、`X-Auth-UI: 1`、直近10分の認証セッションを要求する。リクエスト本文は空 JSON オブジェクトとし、連続操作を制限する。
- `GET /auth/recovery/status` は認証 UI と一致する `Origin`、`X-Auth-UI: 1`、本人のログインセッションを要求し、`{ "issued": boolean, "remaining": number }` を返す。`issued` は使用済み行を含む発行履歴、`remaining` は未使用コードの件数を示し、コードやハッシュは返さない。
- 16文字を4文字ずつハイフンで区切った復旧コードを10件、暗号学的乱数から生成する。旧形式と同じアルファベットを使い、DBには SHA-256 ハッシュだけを保存する。平文は成功レスポンスに一度だけ返し、レスポンス・画面ともキャッシュしない。
- 旧未使用コードの失効と新10件の保存は一つのトランザクションで行う。途中で失敗した場合は旧コードを維持し、503と秘密を含まない Discord アラートを返す。使用済み行は監査のため保持する。
- 再発行の直後から旧コードはログインできない。新コードは本人が安全に保管できるよう画面へ表示する。認証 DB への実データ移行前は公開しない。

旧 Taskly API の GraphQL `recoveryGenerate` と REST `/2fa/recovery/generate` は所有権移管時に停止する。旧 `/auth/login` の復旧コード利用も同じフラグで拒否する。最終コピーと所有権移管が終わるまでフラグを有効にせず、本番のログイン切り替えを行わない。
