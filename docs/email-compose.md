# 認証メールの構成と配信

ログイン、認証設定の追加確認、メールアドレス確認の各コードは、auth プロセス内で日本語・英語の件名、HTML、プレーンテキストに差し込む。宛先と言語は認証 DB の登録情報を使う。3種類ともコードの有効期限は10分である。

完成したメールだけを SMTP に渡す。auth から共有ネットワーク上の `email-compose` gRPC へ認証コードを送らない。`EMAIL_COMPOSE_GRPC_ADDR` は auth の設定から廃止した。SMTP は本番で TLS を必須にし、件名や宛先は送信前に検証する。

切り替え時は auth API の変更を配備し、ログイン・追加確認・メール確認の3種類を実際に受信して本文を確認する。Taskly 本体が使う `email-compose` はこの変更の対象外である。
